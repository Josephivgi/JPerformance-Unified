**New**

- New app icon: a red "JPU" on a dark square.
- Settings > Developer > Use GitHub CLI for update checks. When it is on, update checks use the account you signed in to the GitHub CLI (gh) with, so they never run into GitHub's limit of 60 checks an hour per internet connection. It is off by default.

**Improved**

- The app checks for updates when it opens and every 2 hours, instead of every 30 minutes. Settings > Updates has a Refresh button that checks right away and, if there is a newer version, installs it and restarts.
- An update found earlier stays on screen while the next check runs, and a stalled update download now fails with a message instead of hanging.
- Clean up now only ticks idle shells (Command Prompt, PowerShell, bash) left over from closed apps, and Automatic clean-up only stops those. Left-over node or python programs may be a bot or server you still use, so you tick them yourself. A shell that runs a dev server is never ticked for you.
- Uninstall gives up waiting after 15 minutes on an uninstaller that hangs, so the next uninstall can still run. If an uninstaller fails, you see its error code. If an app left files in Program Files or ProgramData, Uninstall says so instead of skipping them without a word.

**Fixed**

- Stopping an app in Clean up could also stop part of JPerformance Unified's own window when both shared a program name.
- Storage > Biggest folders could open an old scan of a small folder. It now opens your user folder or a drive, and saved results for folders that no longer exist are hidden.
- After clearing a cache, its size could jump back to the old number while sizes were still being measured.
- Leftover files that went to the Recycle Bin stayed in the list when only some of them moved.
- When you delete duplicate files, a copy that changed after the scan is now kept, and at least one copy of each file always stays.
